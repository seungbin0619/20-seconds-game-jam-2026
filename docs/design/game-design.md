# 게임 디자인

[`../prototype.html`](../prototype.html)은 방 하나짜리 원형이다. 이 문서의 확장 기획이 프로토타입보다 우선한다.

## 한 줄 요약

판마다 구조가 바뀌는 작은 집 어딘가에서 폰이 울린다. 소리를 따라 방을 찾고, 쌓인 물건을 치워 20초 안에 받는다.

## 잼 규칙에서 오는 제약

- 한 판은 20초다.
- **판은 서로 독립이다.** 이전 판의 방 상태, 결과, 보상이 다음 판의 게임플레이에 영향을 주면 안 된다.
- 판 사이에 남는 것은 보여주기용 **기록**뿐이다.

## 핵심 재미

- **소리가 유일한 단서다.** 방향, 거리, 덮임에 따른 먹먹함, 벽 너머의 먹먹함, 문 쪽에서 들려오는 소리로 위치를 좁힌다.
- **같은 판이 없다.** 집 구조, 방, 숨는 자리, 발신자, 변수가 매번 바뀐다.
- **결과 칭호와 기록**이 다시 하고 싶게 만든다.

## 한 판의 구조

```
시드 결정 → 무작위 요소 결정 → 집 생성 → 20초 플레이 → 결과(성공/실패, 발신자 반응, 칭호) → 기록 갱신
```

판의 모든 무작위는 시드 하나에서 나온다. 같은 시드면 같은 판이 나오므로 버그 재현에 쓴다.

## 상태 흐름

```
title ──시작──▶ playing ──폰 집기──▶ answer ──슬라이드 완료──▶ won
                  │                   │
                  └──── 시간 종료 ─────┴──────────────────▶ missed

won / missed ──다시 하기 또는 R──▶ playing (새 시드)
```

`answer` 중에도 타이머는 계속 흐른다. R은 `title`을 제외한 모든 상태에서 즉시 새 판을 시작한다.

**일시정지**는 상태가 아니라 `playing`, `answer` 위에 얹히는 플래그다. `playing` 중 포인터 잠금이 풀리면(Esc, 탭이나 창 전환) 자동으로 멈추고, `answer`에서는 Esc로 멈춘다. 멈춘 동안 타이머, 물리, 벨소리가 모두 멈추고 들고 있던 물건은 그 자리에 놓인다. 메뉴는 Resume(다시 잠그고 이어서), Restart(새 판), Title이다. 메뉴에서 Esc를 다시 누르면 재개한다. 단 `playing`에서는 브라우저가 Esc 키 안에서 포인터 잠금을 허용하지 않으므로, 메뉴를 닫고 "Click to resume"을 띄운 뒤 다음 클릭에서 재개한다 (그동안 타이머는 계속 멈춰 있다. 여기서 Esc는 메뉴로 돌아간다). `answer`에서는 Esc로 바로 재개한다. 멈춰 있던 시간은 판 시간에서 뺀다. 벨은 재개하면 패턴 처음부터 다시 울린다.

## 무작위 요소

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 집 구조 | 배치 틀(일자, ㄱ자, T자 등) 위에 방 2~4개 | 필수 |
| 방 종류 | 침실, 거실, 주방, 욕실, 드레스룸 | 필수 (3종부터 시작) |
| 가구 세트 | 방 종류마다 변형 1~2개 | 필수 |
| 숨는 자리 | 가구에 표시된 자리 중 한 곳에 폰. 다른 자리에도 물건 더미 | 필수 |
| 물건 | 더미 높이, 흩어진 물건 수, 종류 비율 | 필수 |
| 시작 위치 | 폰이 없는 방 중 한 곳 | 필수 |
| 발신자 | 발신자마다 고유 벨소리 | 필수 |
| 변수 | 판마다 0~1개 (아래 표) | 필수 |

생성 방식은 [`level-generation.md`](../architecture/level-generation.md)에 있다.

### 변수

| 변수 | 내용 | 우선순위 |
|---|---|---|
| 미끼 소리 | TV 속 전화벨, 알람시계, 태블릿 알림 같은 가짜 소리가 다른 곳에서 난다 | 필수 |
| 진동 모드 | 벨 없이 진동 소리와 물건 떨림만 난다 | 필수 |

| 닫힌 문 | 문 하나가 닫혀 있어 클릭해서 연다. 닫힌 문 너머는 더 먹먹하다 | 선택 |
| 배터리 부족 | 벨이 20초보다 일찍 끊긴다 | 선택 |
| 소음 | 욕실 환풍기나 빗소리가 벨을 가린다 | 선택 |

## 소리 설계

| 단서 | 동작 |
|---|---|
| 방향 | HRTF 3D 음향 |
| 거리 | 거리 감쇠 (`rolloff`) |
| 덮임 | 폰 위 물건 수가 많을수록 고음이 깎인다 |
| 벽 | 폰과 플레이어가 다른 방이면 사이의 벽 수만큼 더 먹먹해진다 |
| 문 쪽 소리 | 다른 방이면 소리가 **폰 방으로 가는 경로의 첫 문 쪽**에서 들린다 |

문을 지날 때 소리가 튀지 않도록 다음을 지킨다 (오디오 검증에서 확인).

- 거리는 문을 경유하는 경로 길이로 잰다. 문 앞에서 커졌다가 통과 후 작아지는 일이 없다.
- 문에서 `doorBlendRadius` 안으로 들어오면 방향이 문 쪽에서 폰 쪽으로 서서히 돌아가고, 벽 한 겹이 서서히 걷혀 문턱에서 다 걷힌다.

벽과 경로는 레이캐스트가 아니라 생성 시 만든 **방 그래프**로 계산한다.

## 규칙

| 항목 | 내용 |
|---|---|
| 판 준비 | 모든 숨는 자리에 물건 더미를 쌓고, 그중 한 자리의 맨 아래에 폰을 둔다 |
| 흩뿌림 | 방마다 바닥에 물건을 몇 개 흩뿌린다 |
| 안정화 | 시작 전에 물리를 90스텝 돌려 더미를 가라앉힌다 |
| 폰 집기 | 도달 거리 안, 화면 중심 레이와 폰의 거리 0.17m 이내, 사이에 가림막 없음 |
| 물건 잡기 | 누르면 조준한 물건을 카메라 앞 잡는 점(0.9m 앞, 눈높이 -0.25m)으로 끌어온다 (약 0.1초). 잡은 채로 걷고 둘러볼 수 있다 |
| 깔린 물건 | 위에 다른 물건이 얹혀 있으면 잡히지 않는다. 손 쪽으로 옆으로 6cm쯤 끌려 나오다 멈춘다. 더미는 위에서부터 치워야 한다 |
| 물건 던지기 | 떼면 시선 수평 방향 2.0, 위 1.8의 기본 토스에 휘두른 속도(잡는 점의 최근 0.08초 이동 속도) × 0.6을 더해 던진다. 최대 9m/s. 시선을 휙 돌리며 떼면 그 방향으로 날아간다 |
| 놓치기 | 가구에 걸려 잡는 점에서 0.9m 넘게 멀어지거나 0.6초 안에 손에 들어오지 않으면 그 자리에 떨어뜨린다 |
| 벽 앞에서 잡기 | 눈과 잡는 점 사이에 벽이나 가구가 있으면 잡는 점을 그 앞으로 당긴다. 물건이 문틀을 돌아 옆방으로 끌려가지 않는다 |
| 바구니처럼 벽이 있는 곳의 물건 | 먼저 0.6m 수직으로 들어 올리고, 손에 들어올 때까지 그 높이 아래로 내리지 않는다 |
| 덮임 수 | 폰 기준 높이 -0.03~+1.1m, 물건 로컬 XZ 범위 + 0.05m 안에 드는 물건 수 |
| 진동 | 벨 한 주기의 절반마다 폰 반경 0.5m, 높이차 0.6m 안의 물건을 살짝 튀게 한다. 벨이 울리는 판에서는 가까이서만 보이게 약하게(`ringJiggleScale`), 진동 모드 판에서는 원래 세기로 튄다. 소리가 주 단서이고 떨림은 보조 단서다 |
| 폰 흔들림 | 덮인 물건이 0개일 때만 폰이 좌우로 진동한다 |
| 받기 | 폰을 집으면 포인터 잠금이 풀리고 커서가 보인다. 슬라이드 손잡이를 클릭한 채 트랙 끝까지 끈다. 중간에 놓으면 처음 자리로 돌아간다 |
| 실패 연출 | 폰 화면이 빨갛게 바뀌고 결과 화면이 바로 뜬다. 시선을 폰 쪽으로 돌리거나 벽 너머로 폰을 비추는 연출은 시도했다가 뺐다 (11/13: 폰이 다른 방이나 더미 속에 있으면 잘 보이지 않았다) |

타이머는 **실제 시간**으로 줄어든다. 게임 시간 스케일이나 프레임 드랍 보정의 영향을 받지 않는다.

## 결과 칭호

그 판 안에서만 판정한다. 조건을 만족한 것 중 우선순위가 가장 높은 하나를 결과 화면에 표시한다.

| 칭호 | 조건 |
|---|---|
| Speedrunner | 3초 안에 받기 |
| Buzzer Beater | 0.5초 이하로 남기고 받기 |
| Sniper | 던진 물건에 맞은 더미에서 폰이 드러남 |
| Neat Freak | 한 번도 던지지 않고 받기 |
| Tornado | 물건을 15개 이상 던짐 |

## 기록

판 사이에 남는 유일한 데이터다. 게임플레이에는 영향을 주지 않는다.

- 저장 항목: 최고 기록(가장 빨리 받은 시간), 받은 전화 수와 놓친 전화 수, 만난 발신자, 얻은 칭호, 찾은 이스터에그
- 타이틀 화면에서 본다.
- Web에서는 `PlayerPrefs`가 브라우저 저장소(IndexedDB)에 저장되므로 브라우저마다 따로 남는다.

## 후순위: 숨겨진 요소

15일 범위 밖이다. 여유가 생기면 이 순서로 넣는다.

1. 희귀 발신자 (미래의 나, 산타 등 낮은 확률, 전용 벨소리와 문구)
2. 더미 속 숨은 물건 (리모컨, 지폐 등. 결과 화면에 "Also found" 표시)
3. 방 반응 (TV 맞히면 채널 변경, 바구니에 넣으면 "3-pointer!")
4. 희귀 폰 (플립폰은 받는 방식이 다름)
5. 고양이 (폰 위에 앉아 있거나 물고 이동)

| `doorBlendRadius` | 1.5 | 문에서 이 거리(m) 안이면 소리 방향과 벽 가림이 서서히 바뀐다 |
| `emitterFollowSpeed` | 6 | 소리 경로가 바뀔 때 따라가는 속도(1/s) |
| `ringGainStart` | 0.5 | 판 시작 시 벨 볼륨 |
| `ringGainEnd` | 1.2 | 시간이 다 됐을 때 벨 볼륨. 더 올리면 가까이서 소리가 깨진다 |
| `phoneAimRadius` | 0.17 | 화면 중심 레이와 폰 중심의 거리가 이 값(m) 이하면 폰을 조준한다 |
| `phoneSpotJitter` | (0.06, 0.05) | 숨는 자리 중심에서 폰을 옮기는 최대 거리(m), 자리 기준 좌우·앞뒤 |
| `phoneYawJitter` | 28.6 | 폰을 자리 방향에서 돌리는 최대 각도(도) |
| `coverBelow` | 0.03 | 폰 중심보다 이만큼(m) 아래까지 중심이 있는 물건을 덮임으로 센다 |
| `coverAbove` | 1.1 | 폰 중심보다 이만큼(m) 위까지 중심이 있는 물건을 덮임으로 센다 |
| `coverMargin` | 0.05 | 물건 가로세로 범위를 이만큼(m) 넓혀 폰이 안에 들면 덮임 |
| `phoneShake` | 0.004 | 덮인 물건이 없을 때 폰이 좌우로 떠는 폭(m) |
| `phoneShakeRate` | 90 | 폰이 떠는 빠르기(rad/s) |
| `screenBlinkRate` | 20 | 울리는 동안 화면이 깜박이는 빠르기(rad/s) |
| `screenBlinkDim` | 0.35 | 깜박일 때 어두운 쪽 밝기 비율 |
| `jiggle` | 0.55 | 진동 시 튀는 속도 (진동 모드 기준) |
| `ringJiggleScale` | 0.4 | 벨이 울리는 판의 진동 세기 배율 (튀는 속도와 회전). 프로토타입 세기는 너무 눈에 띄어 찾기 쉬웠다 (잠정) |
| `jiggleDelay` | 0.3 | 판 시작 후 첫 진동까지(초) |
| `jiggleInterval` | 1.0 | 진동 간격(초). 기본 벨 한 주기(2초)의 절반 |
| `jiggleRadius` | 0.5 | 폰에서 이 수평 거리(m) 안의 물건을 튀게 한다 |
| `jiggleHeight` | 0.6 | 폰과 높이 차가 이 값(m) 안인 물건을 튀게 한다 |
| `jiggleSpin` | (1, 1.5, 1) | 진동 시 무작위 회전 속도 최대값 (rad/s, 축마다 ±) |
| `hintDuration` | 4 | 판 시작 후 힌트 문구를 보여주는 시간(초) |
| `lowTimeWarning` | 5 | 남은 시간이 이 값(초) 이하면 타이머가 빨갛게 바뀐다 |
| `resultInputDelay` | 0.6 | 결과가 나온 뒤 이 시간(초) 동안은 클릭으로 새 판을 시작하지 않는다 |
| `modifierChance` | 0.5 | 판에 변수가 붙을 확률 (잠정) |
| `roomCount` | 2~4 | 방 개수 범위 |

먹먹함 공식: `cutoff = max(minCutoff, clear × (covered / clear) ^ (min(1, covers / maxCovers) ^ 0.6) × wallCutoffScale ^ walls)`. `walls`는 문 근처에서 소수가 된다. `answer` 상태에서는 `clearCutoff`로 고정한다.
벨 볼륨: `lerp(ringGainStart, ringGainEnd, 경과시간/전체시간) × wallGainScale ^ walls`. 프로토타입(0.75→1.2)은 커지는 느낌이 약해 시작 볼륨을 낮췄다.

벽은 고음 깎기와 볼륨 감소를 함께 준다. 벨 기본음이 660~1480Hz라서 고음 깎기만으로는 벽 너머 느낌이 약했다 (오디오 검증에서 확인).

벽 효과를 조정할 때 알아둘 점:

- 고음을 깎으면 귀가 민감한 2~5kHz 대역이 빠져서 볼륨이 같아도 훨씬 작게 들린다. `wallCutoffScale`만 내려도 "작아지는" 느낌이 난다.
- 문 전환 구간(`doorBlendRadius` 1.5m)은 걷는 속도로 약 0.5초다. 전환이 급하게 느껴지면 이 값을 늘린다.
- 거리 감쇠(`rolloff` 2.2)도 크다. 경로 6.9m → 3.8m에서 볼륨이 약 2배가 된다.
- 테스트 씬(`Feature/Ringtone/Sandbox`)의 슬라이더로 Web 빌드에서 귀로 맞출 수 있다.

## 효과음

현재 효과음(던지기, 집기, 성공, 실패)은 프로토타입 소리를 옮긴 **임시**다. 폴리시 단계에서 확정한다.

## 아트 방향: Last Ring

**집은 차갑고 무심하게, 폰만 뜨겁게. 20초 동안 화면이 조여 온다.** 따뜻하고 아늑한 분위기는 쓰지 않는다 (11/13 결정).

### 톤

- 플레이 중에는 쫓기는 긴박함을 준다.
- 결과 화면의 발신자 문구는 지금처럼 가볍게 둔다. 긴장이 풀리면서 웃게 만드는 반전이다 (잠정).

### 색과 조명

- 실내는 푸르스름한 형광등과 창밖 새벽빛으로 비춘다. 벽, 바닥, 가구는 채도를 낮춘 청회색 계열로 칠한다.
- **노랑과 따뜻한 빛은 폰과 UI 전용이다.** 집 안 다른 곳에는 쓰지 않는다.
- 물건 더미도 채도를 낮춘다. 폰이 드러나는 순간이 튀어야 한다.

### 풀스크린 셰이딩

URP Full Screen Pass 하나에 셰이더 하나를 쓴다. 기본 룩과 시간 연출을 같은 셰이더에서 처리한다. 구현은 `Feature/ScreenFx`(`ScreenFx.shader`, `ScreenFxDriver`)에 있다. `Missed Call/Screen Fx/Install Renderer Feature` 메뉴가 머티리얼을 만들고 PC, Mobile 렌더러에 기능을 넣는다. 드라이버의 `previewTimeLeft`를 0 이상으로 두면 남은 시간별 화면을 에디터에서 볼 수 있다.

| 층 | 내용 |
|---|---|
| 잉크 외곽선 | 깊이와 노멀의 경계에 굵은 선을 긋는다. 선 색은 배경색 `#10161C`. 선 두께는 화면 높이에 비례한다. 회색 박스 가구를 일부러 그린 그림처럼 보이게 하는 것이 목적이다 |
| 음영 단계 | 밝기를 2~3단으로 끊는다. 색상은 유지한다. 폰 화면처럼 밝게 빛나는 곳은 맨 윗단 위로 그대로 둔다 |
| 시간 연출 | 남은 시간에 따라 조여 온다 (아래 표) |

| 남은 시간 | 연출 |
|---|---|
| 20~10초 | 기본 룩만 |
| 10~5초 | 비네트가 서서히 좁혀지고 채도가 떨어진다 |
| 5~0초 (`lowTimeWarning`) | 벨 박자에 맞춰 붉은 기운(`#FF6B57`)이 맥박처럼 깜박인다. 외곽선이 떨리고 굵어진다. 가장자리에 색수차 |

- 시간 연출은 `playing`과 `answer`에서만 켠다. 타이틀과 일시정지에서는 기본 룩만, `missed`에서는 붉은 기운을 한 번 번쩍인 뒤 유지한다.
- 손그림 수채(`style/sketch`)는 시간 연출도 그림체 안에서 한다. 비네트 대신 가장자리부터 연필 빗금이 차오르고(세지면 반대 방향 빗금이 겹침), 붉은 맥박 대신 어두운 남색 먹물이 가장자리부터 화면을 잠식한다 (붉은색은 피처럼 보여서 뺐다). 물감은 남은 시간에만 따라 넓어지고 물러나지 않으며(10초부터 조금, 마지막 5초에 크게, 0초에는 가운데만 남음), 벨 박자는 번진 끝을 조금 밀어 넣고 고인 안료를 진하게 할 뿐이다. 놓치면 다 잠긴 화면에서 멈춘다. 종이는 시간이 갈수록 어둡고 푸르게 바뀌고, 마지막 5초에는 외곽선이 크게 어긋나게 덧그려진다.
- 외곽선은 모든 물체에 똑같이 그린다. 폰을 강조해 소리 단서를 대신하지 않는다.
- 마지막 5초에는 심장 박동 효과음을 넣는다. 벨 기본음(660~1480Hz)을 가리지 않게 100Hz 이하로 만든다. 째깍 소리는 고음이라 벨과 겹치므로 쓰지 않는다.
- Web: 셰이더와 머티리얼은 에셋으로 참조한다. 외곽선에 깊이·노멀 사전 패스가 필요하므로 저성능 환경(소프트웨어 렌더러 감지, FPS 저하)에서는 외곽선을 끄고 색 처리만 남긴다.

| 키 | 값 | 설명 |
|---|---|---|

| `fxOutlineDepthThreshold` | 0.1 | 깊이 차가 이 비율 이상이면 경계 |
| `fxOutlineNormalThreshold` | 0.4 | 노멀 차(1 - 내적)가 이 값 이상이면 경계 |
